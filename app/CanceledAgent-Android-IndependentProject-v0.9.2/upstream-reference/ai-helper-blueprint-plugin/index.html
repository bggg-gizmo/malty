What Is the Blueprint?

      
    
        
  • A behavioral protocol for AI sessions. The blueprint gives the AI a consistent set of rules to follow — design principles, file management, conversation history, and task tracking.
    • 
        
  • Two operating modes. Core mode for quick, lightweight sessions. Full mode for long-term projects that accumulate context worth keeping across sessions.
    • 
        
  • Three stackable sub-modes. On top of either mode, a session can stack capability layers — image editor (raster editor: layers, selection, filters, AI generation — with a painting surface of 1100 brushes in named brushsets, palettes, papers and a bakeable relighting pass, merged in from the canvas extension), 3D editor (three.js studio + animation lab, plus the human cast merged in from the Human 3D editor extension: 77 rigged humans behind a scriptable window.CharacterAPI — cast, pose, material, lighting, clip, camera, screenshot, share link — and a paint-on-the-mesh texture studio), and tilemap and sprite editor (a sprite/tileset workbench with a scriptable pixel engine: sheet splitting, atlases with frame metadata, retro palettes, SVG tracing, GIF/APNG, and SpriteFusion tilemap round-trips). They combine freely, e.g. Full-image editor-tilemap and sprite editor.
    • 
        
  • Three overlays — git, thinking and plugins — all on by default. Overlays ship with this plugin rather than the master. Git is the default working discipline: the project is a versioned codebase from the first commit, so the AI clones it, commits each meaningful change with a message, and shows history and diffs — that is what keeps steering and control on by default. Thinking puts the AI helper's reasoning in a picture-in-picture window beside the output as a unified pipeline (each entry sequenced, typed and linked to its parent, with trace and export): since the model provider no longer shows you its reasoning, this window is where the thinking lives — you rate pivots 👍/👎, revert a linked change, and copy the ratings out as instructions for the next step. Back-thinking is part of it: the pipeline starts when the overlay does, so reasoning you can already see — whatever the provider does show, and the rounds that happened before the log existed — is mirrored into the same chain verbatim (never summarized) with root.aiThinkVerbatim for a visible block and root.aiThinkBackfill for whole earlier rounds, which renumbers and chains them so the trace reads as one line of thought. Plugins carries the offline catalog of every Perchance plugin — 195 of them, with source, declared imports and exposed names — plus the browsing inspector as a PiP window whose per-plugin toggles copy ready-to-paste import lines, and a no-import registry the AI can query with no setup at all. The two windowed overlays appear only while editing: a published page renders neither, so no thought text or catalog keeps loading there.
    • 
        
  • Self-documenting. Conversation history, task lists, and version history are maintained in src/ so nothing is lost between sessions.
    • 
        
  • Installable as a plugin. Any project can run it by importing ai-helper-blueprint-plugin and pointing its main.pjs at the mirrored copy — no file copying, and updates arrive with the plugin.
    • 
        
  • Easy to use. Just point a new AI Helper session at this generator and tell it to read main.pjs. The blueprint handles the rest.
    • 
        
  • Prompt-driven. The plugin page's mode builder (editor view only) writes a paste-ready activation prompt — mode, sub-modes, overlays, and the exact install lines — so a new session starts configured instead of being asked, and the live text resolver means it always pulls the newest blueprint rather than a frozen copy.
